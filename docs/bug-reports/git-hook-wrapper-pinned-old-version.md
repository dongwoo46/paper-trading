## 1. 한 줄 요약
플러그인을 1.2.0 으로 올린 뒤에도 소비 레포 `.git/hooks` 래퍼가 0.95.0 캐시 경로를 불러, 커밋 훅이 1.2.0 조항(AP10·WI10)을 unknown-clause 로 막았다.

## 2. 환경 (provenance)
- 레포 / 컨텍스트: paper-trading 규칙 이사(chore/repo-rules-devkit-dedupe)
- devkit 버전: 1.2.0(세션) · 훅 래퍼 0.95.0
- gitSha: c4e51fa 커밋 직전
- 모드 / tier: 미상
- OS / 런타임: macOS(Darwin 25.6.0)

## 3. 재현 절차 (결정적으로)
1. devkit 0.95.0 시절에 git 훅을 설치한 소비 레포를 둔다.
2. 플러그인을 1.2.0 으로 올린다(훅 재설치 없음).
3. 1.2.0 에만 있는 조항 기호를 인용한 규칙 파일을 커밋한다.

## 4. 기대 동작 vs 실제 동작
- 기대: 훅이 세션과 같은 devkit 버전으로 돌거나, 버전 어긋남을 세션 시작에 알림.
- 실제: 래퍼가 옛 버전 경로를 그대로 불러 새 조항을 모름. 사람이 sed 로 래퍼 경로를 1.2.0 으로 고쳐서 풀었다.

## 5. 영향 (impact)
- 무엇이 깨지나: 업그레이드 뒤 소비 레포의 커밋 게이트가 옛 판정으로 돈다. 새 조항은 거짓 차단, 새 검사는 조용히 빠짐.
- 심각도: high(게이트 오작동, 조용히 옛 규칙 적용)

## 6. 근본 원인 (추정 — 딱지)
`추정` 래퍼가 버전 박힌 절대 경로를 적고, 업그레이드 때 래퍼를 다시 쓰거나 버전 대조하는 단계가 없다. 근거: 사람이 고친 것이 래퍼 안 경로 문자열 하나였다.

## 7. 관련 파일 · 링크
- tools/git-hooks-status.js(점검 도구 — 이번에 어긋남을 알렸는지는 미상)
- 인계문서 docs/sessions/2026-11-21-repo-rules-devkit-migration.md §5 1번

## 8. (선택) 수정 제안
래퍼가 버전 없는 현재 플러그인 루트를 풀어 부르게 하거나, 세션 시작에 래퍼 버전과 세션 버전을 대조해 다르면 재설치를 안내.
