# 하네스 엔지니어링 정리 (Harness Analysis)

이 폴더는 `paper-trading` 프로젝트에 구축된 **Claude Code 하네스 엔지니어링**(자동화 환경 설정)을
한글로 이해하기 쉽게 정리한 문서 모음입니다.

> "하네스(harness)"란 AI 에이전트가 실제로 일을 할 수 있도록 감싸는 **실행 환경/도구 세트**를 말합니다.
> 단순히 프롬프트를 잘 쓰는 것을 넘어, **커맨드 · 에이전트 · 스킬 · 훅 · 상태 파일**을 조합해
> "혼자서도 안전하게 굴러가는 개발 파이프라인"을 만든 것입니다.

---

## 한눈에 보기

이 프로젝트의 하네스는 **5개 축**으로 구성됩니다.

| 축 | 위치 | 역할 | 개수 |
|----|------|------|------|
| **커맨드(Commands)** | `.claude/commands/*.md` | 사용자가 `/명령`으로 호출하는 진입점 | 8개 |
| **에이전트(Agents)** | `.claude/agents/*.md` | 각 역할(기획/개발/리뷰/QA)의 페르소나와 규칙 | 7개 |
| **스킬(Skills)** | `.claude/skills/*.md` | 에이전트가 참조하는 도메인 지식 모듈 | 7개 |
| **훅(Hooks)** | `.claude/hooks/*` + `settings.json` | 도구 실행 전/후 자동 개입(가드·검증·알림) | 7개 |
| **상태(State)** | 루트 `docs/` | 오케스트레이터의 단일 진실 공급원(SSOT) | — |

이 다섯이 맞물려 **"기획 → 구현 → 테스트 → 리뷰 → 정리/PR"** 한 사이클이
사람의 최소 개입만으로 돌아갑니다.

## 핵심 설계 철학 (요약)

1. **중앙 통제탑(Orchestrator)이 모든 흐름을 조율** — 사람은 의사결정만, 실행은 서브에이전트가.
2. **컨텍스트 격리** — 각 서브에이전트는 매번 새 컨텍스트로 시작. 필요한 파일은 step 문서에 명시.
3. **2-pass 기획** — 기획자는 (A) 질문 먼저 → 사용자 확정 → (B) 문서 작성. 독단적 결정 금지.
4. **TDD 강제** — Red(실패 테스트) → Green(최소 구현) → Refactor. 훅이 이를 상기시킴.
5. **금융 안전** — 금액/수량은 절대 부동소수점 금지(`BigDecimal`/`Decimal`).
6. **안전 가드** — `rm -rf`, `git reset --hard`, `DROP TABLE` 등 위험 명령을 훅이 자동 차단.
7. **상태 영속화** — 세션이 끊겨도 `docs/`의 상태 파일로 정확히 재개 가능.

> ⚠️ 이 문서들은 **읽기 전용 정리본**입니다. 실제 동작 규칙의 원본은
> `.claude/`, `CLAUDE.md`, `.codex/`, `codex.md`에 있으며 그 파일들은 수정하지 않습니다.
