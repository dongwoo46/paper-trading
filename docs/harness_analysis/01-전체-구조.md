# 01. 하네스 전체 구조

## 1. 디렉토리 맵

```
paper-trading/
├── CLAUDE.md                      # 프로젝트 전역 규칙 (모든 세션에 자동 주입)
│
├── .claude/                       # ★ 하네스 본체
│   ├── settings.json              # 훅 등록 + 권한 설정 (어떤 훅을 언제 실행할지)
│   ├── settings.local.json        # 로컬 전용 권한 추가
│   ├── failure-log.json           # 장애 패턴 누적 카운터 (track-failure 훅이 기록)
│   │
│   ├── commands/                  # 슬래시 커맨드 8개 → 각자 agents/ 파일을 @import
│   │   ├── orchestrate.md         #   /orchestrate
│   │   ├── plan.md / plan-quant.md
│   │   ├── build.md / build-quant.md
│   │   ├── review.md / test.md / cleanup.md
│   │
│   ├── agents/                    # 에이전트 페르소나 7개 → 각자 skills/ 를 @import
│   │   ├── orchestrator.md        #   중앙 통제탑 (가장 큼, 400줄)
│   │   ├── service-planner.md / quant-planner.md
│   │   ├── fullstack-dev.md / quant-dev.md
│   │   ├── code-reviewer.md / test-engineer.md / cleanup.md
│   │
│   ├── skills/                    # 도메인 지식 모듈 7개 (에이전트가 참조)
│   │   ├── tdd.md / ddd.md / clean-architecture.md
│   │   ├── api-design.md / system-design.md / quant.md / review.md
│   │
│   └── hooks/                     # 자동 개입 스크립트 7개
│       ├── pre-bash-guard.sh      #   [실행 전] 위험 명령 차단
│       ├── validate-build.sh      #   [Edit/Write 후] 변경 서비스 기록
│       ├── compile-dirty.sh       #   [작업 종료 시] 변경 서비스만 컴파일
│       ├── post-test-check.sh     #   [Bash 후] 테스트 실패 시 TDD 상기
│       ├── track-failure.sh       #   [Bash 후] 명령 실패 분류·누적
│       ├── on-stop.sh / notify.sh #   [작업 종료 시] 현황 요약 + 알림
│       └── play-sound.ps1         #   Windows 소리 재생 보조
│
└── docs/                          # ★ 오케스트레이터 상태 (단일 진실 공급원)
    ├── state.md                   #   현재 모드/상태/활성 Phase
    ├── TODO.md                    #   백로그 (기능 목록)
    ├── ADR.md / PRD.md            #   설계 결정/제품 요구
    ├── phase/{project}/{feature}/ #   진행 중인 기능의 단계별 문서
    │   ├── index.json             #     상태 머신 (step 진행도)
    │   ├── spec.md                #     기획 산출물
    │   └── step-1.md ~ step-N.md  #     각 단계 지시서
    └── done/                      #   완료된 기능 아카이브
```

> **중요 규칙**: 오케스트레이터 상태는 **오직 루트 `docs/`**에만 존재합니다.
> `.claude/**/docs`, `.codex/**/docs` 같은 중복 위치는 읽지도 쓰지도 않습니다.

## 2. 4단계 참조 체인 (@import)

이 하네스의 핵심 구조는 **얇은 진입점 → 두꺼운 본체** 로 갈수록 구체화되는 계층입니다.

```
[사용자 입력]
   /build
      │
      ▼
[커맨드]  .claude/commands/build.md      ← 3줄짜리 얇은 파일
      │   @../agents/fullstack-dev.md     (에이전트를 import)
      ▼
[에이전트] .claude/agents/fullstack-dev.md ← 역할·실행순서·규칙
      │   @../skills/tdd.md
      │   @../skills/clean-architecture.md  (스킬을 import)
      │   @../skills/ddd.md
      ▼
[스킬]    .claude/skills/tdd.md 등         ← 재사용되는 도메인 지식
```

- **커맨드**는 "어떤 에이전트를 부를지"만 정하는 라우터입니다.
- **에이전트**는 "그 역할이 어떻게 일하는지"를 정의합니다.
- **스킬**은 여러 에이전트가 **공유**하는 지식입니다. (예: `tdd.md`는 fullstack-dev·quant-dev·test-engineer가 모두 참조)

이렇게 하면 지식이 한 곳(스킬)에 모여 중복이 없고, 에이전트는 자기 역할에만 집중합니다.

## 3. 5개 축이 맞물리는 그림

```
            ┌──────────────────────────────────────────────┐
            │  CLAUDE.md  (전역 규칙: 금융 안전, TDD, 커밋 한글…) │
            └──────────────────────────────────────────────┘
                              │ 모든 에이전트가 따름
                              ▼
  ┌──────────┐   호출    ┌──────────────┐   읽고/쓴다   ┌──────────────┐
  │ 커맨드   │ ───────▶ │  에이전트     │ ◀──────────▶ │ docs/ 상태   │
  │ /xxx     │          │ (페르소나)    │   index.json │ (SSOT)       │
  └──────────┘          └──────────────┘   state.md    └──────────────┘
                              │ @import
                              ▼
                        ┌──────────────┐
                        │ 스킬 (지식)   │
                        └──────────────┘

  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
  훅(Hooks): 위 모든 도구 호출의 "전/후"에 자동으로 끼어듦
    • 도구 실행 전  → pre-bash-guard (위험 명령 차단)
    • 파일 수정 후  → validate-build (변경 추적)
    • Bash 실행 후  → post-test-check, track-failure
    • 작업 종료 시  → compile-dirty, on-stop, notify
```

- **세로축(커맨드→에이전트→스킬)**: 일을 *어떻게* 할지를 정의.
- **가로축(에이전트↔docs)**: 일의 *진행 상태*를 저장하고 재개.
- **훅**: 위 흐름을 가로질러 *안전과 자동화*를 보장.
- **CLAUDE.md**: 그 위에서 모두가 지키는 *헌법*.

## 4. 왜 이렇게 만들었나 (설계 의도)

| 문제 | 하네스의 해법 |
|------|--------------|
| AI가 컨텍스트를 잃으면 작업 맥락이 사라짐 | `docs/`에 상태 영속화 → 세션 끊겨도 재개 |
| AI가 너무 많은 파일을 읽어 비용 폭증 | step 문서에 "읽을 파일"만 명시 + 변경 파일만 리뷰/테스트 |
| AI가 독단적으로 설계를 결정 | 2-pass 기획 + 승인 게이트 |
| AI가 위험한 명령을 실행 | pre-bash-guard 훅이 차단 |
| 매 수정마다 전체 빌드 → 느림 | dirty 목록에 모아 작업 종료 시 1회만 컴파일 |
| 같은 장애가 반복되는데 학습 안 됨 | track-failure가 누적 → 5회 시 CLAUDE.md에 기록 |
| 금융 계산 실수 = 치명적 | 금액/수량 `BigDecimal`/`Decimal` 강제 (전역 규칙) |

다음 문서들에서 각 축을 하나씩 자세히 설명합니다.
