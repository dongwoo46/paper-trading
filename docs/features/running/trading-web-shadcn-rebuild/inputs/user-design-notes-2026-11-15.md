## E. 단계 구상 1 (원장부터)

### Step 1. 로컬 가상 투자 원장부터 완성
외부 브로커 없이 네 로컬에서만 정확히 돌아가게 만든다.
포함: 주문, 체결, 예수금, 포지션, 손익, 부분 체결, 취소, 홀드/해제
이 단계에서 네가 진짜 증명하는 건: 외부에 의존하지 않아도 금융 상태 엔진을 설계할 수 있다는 점이다.

### Step 2. 시세 기반 가상 체결 엔진 연결
이미 가져온 웹소켓 데이터 활용. 예: 시장가 주문 → 현재가 또는 best ask/bid 기준 체결, 지정가 주문 → 가격 조건 만족 시 체결, 슬리피지는 일단 단순화 가능.
이 단계에서: 수집 데이터와 주문 엔진이 연결된다.

### Step 3. KIS 모의투자 연동
이제 로컬 원장을 외부 paper broker 와 연결한다. 핵심: 외부 주문번호 저장, 체결 조회/실시간 통지 반영, 로컬 원장과 외부 결과 reconcile.
여기서 중요한 점은 로컬 엔진이 먼저 완성되어 있어야 외부 연동 디버깅이 가능하다는 것이다.

### Step 4. 실제 투자 연동
이건 마지막이다. 왜냐하면: 실제 돈이 들어가므로 검증되지 않은 상태 머신이면 위험, paper 에서 정합성 검증 후 넘어가야 함.

### Step 5. 백테스트 / AI 전략 / LangGraph
이건 «실행 엔진»이 안정화된 뒤다. 왜냐하면 전략이 아무리 좋아도 실행 결과를 저장하고 평가할 원장이 없으면 다 무너진다.

## F. 서비스 정의

그니까 지금 내가 만드는 서비스는 이거야: 모의투자 + 자기 개인의 투자 전략 테스트 + 내가 이때 이거 샀으면... 어떻게 되었을까 (나의 성향 기반 수익률 테스트) + mirofish 활용 어떤 주제에 대해서 ai 끼리 투자한 거 기반 모의투자 + 여러 주식, 뉴스 정보 획득해서 투자계획 전략 세우기

## G. 단계 구상 2 (ep 1~9, 시뮬레이션 중심)

- ep 1. 프로젝트 뼈대: Spring Boot, Java 21, Gradle, PostgreSQL, Flyway, Testcontainers, 공통 예외 처리 / 응답 포맷. 결과물: 프로젝트 실행 가능, DB 마이그레이션 가능, 통합 테스트 가능
- Step 2. 종목/가격 데이터: Stock, Candle, 종목 등록, 가격 데이터 저장, 날짜 기준·기간 기준 가격 조회. 결과물: 특정 종목의 특정 날짜 가격을 읽을 수 있음. 이게 되어야 시뮬레이션이 가능하다
- Step 3. 가상 계좌: VirtualAccount, 초기 자본금, 현금 잔고, 계좌 조회. 결과물: 내 실험용 계좌 하나 생성 가능
- Step 4. 주문/체결/포지션 (핵심): 매수·매도 주문, 주문 상태, 체결 처리, 평균 단가 계산, 보유 수량 관리, 손익 반영. 결과물: 계좌에서 종목을 사고 팔 수 있음, 체결 후 포지션이 맞게 반영됨
- Step 5. «이때 샀으면» 기능: 종목 선택, 과거 날짜 선택, 금액 입력, 해당 시점 매수 가정, 현재 시점 손익 계산. 결과물: 가장 직관적인 사용자 가치 제공. 초반 데모 기능으로도 좋다
- Step 6. 전략 인터페이스: TradingStrategy 인터페이스, StrategyContext, StrategySignal, 기본 전략 1개 (추천 첫 전략: 이동평균 돌파 전략). 결과물: 수동 매매가 아니라 룰 기반 투자 가능
- Step 7. 백테스트 엔진: 기간 설정, 전략 선택, 초기 자본, 날짜 순회, 전략 평가, 주문/체결 재현, 결과 저장. 결과물: 특정 전략을 과거 데이터에 돌려볼 수 있음
- Step 8. 분석: 총 수익률, 누적 수익률, 승률, 평균 손익, 최대 낙폭, 거래 내역. 결과물: 전략이 진짜 괜찮은지 해석 가능
- Step 9. AI / mirofish: 주제 입력, 에이전트별 의견 생성, 의견 집계, 전략 후보 제안, 시뮬레이션 실행. 결과물: AI 기반 투자 실험 가능. 이건 마지막이다

### MVP 기준
- 꼭 넣을 것: 종목, 가격 데이터, 가상 계좌, 주문/체결, 포지션, «이때 샀으면», 기본 전략 1개, 백테스트
- 나중에 넣을 것: 실시간 시세, 뉴스 수집 자동화, 외부 증권 API, WebSocket, 멀티 에이전트 투자, 고급 통계, 포트폴리오 리밸런싱

## H. 기능 상세 정의 (6개 도메인)

### 1. 계좌 및 투자 실행 (Execution Domain)
목적: 실제 거래 흐름과 동일한 구조로 모의투자 실행
- 모의투자 계좌 연결: 한국투자 / 키움 API 연동, 토큰 관리
- 주문 생성: 매수 / 매도, 지정가 / 시장가
- 주문 상태 관리: 접수, 체결 대기, 체결 완료, 실패
- 체결 처리: 체결 이벤트 수신, 부분 체결 처리
- 포지션 관리: 보유 종목, 평균 단가, 수량
- 잔고 관리: 예수금, 평가 금액

### 2. 전략 관리 (Strategy Domain)
목적: 사용자 및 AI 전략 정의 및 실행
- 전략 생성: 조건 기반 (ex: RSI, 이동평균), 사용자 정의 룰
- 전략 실행 ON/OFF
- 전략 로그 저장: 어떤 조건으로 매수/매도했는지 기록
- 전략별 주문 생성

### 3. 시뮬레이션 (Simulation Domain)
목적: 과거 기반 투자 실험
- «이때 샀으면?» 시뮬레이션: 특정 시점 기준 매수, 현재까지 수익률 계산
- 백테스트: 과거 데이터 기반 전략 실행
- 이벤트 리플레이: 과거 가격 흐름 재생, 동일 전략 재실행

### 4. AI / 데이터 기반 의사결정 (Intelligence Domain)
목적: 전략 생성 및 투자 판단 보조
- 뉴스 수집: 외부 API (Reuters, Finnhub 등)
- 뉴스 분석: 키워드 추출, 감정 분석
- AI 전략 생성: 뉴스 기반 매수/매도 시그널 생성
- Mirofish 기반 멀티 에이전트 투자: 여러 AI 가 의견 생성, 의견 집계 후 투자 결정

### 5. 결과 분석 (Analytics Domain)
목적: 투자 결과 평가 및 전략 개선
- 수익률 분석: 일별 / 누적
- 거래 내역 조회: 주문 / 체결 히스토리
- 전략 성과 분석: 전략별 수익률, 승률
- 투자 로그 분석: 왜 매수/매도 했는지

### 6. 실시간 처리 (Realtime Domain)
목적: 투자 상태 즉시 반영
- 실시간 가격 반영: WebSocket / Stream
- 실시간 주문 상태 업데이트
- 실시간 손익 계산
- 사용자 UI 실시간 업데이트
