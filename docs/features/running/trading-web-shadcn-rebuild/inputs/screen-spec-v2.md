# 공통 사양서 v2 (디자인 시스템 비교용)

shadcn / Astryx / Ant Design / Mantine 네 구현이 «같은 내용»을 보여주기 위한 정보 구조 사양이다.
색·간격·모양·컴포넌트 선택은 각 시스템이 정한다. 이 문서는 «무엇이 어디에 보이는가»만 정의한다.
근거: paper-trading README(실시간 시세 수집 → 모의 주문·체결 → 전략 엔진 → AI 전략 연구). 데이터 버전 `SHARED_VERSION = 2`.

## 0. 공통 규칙

1. 데이터는 `data.ts`, 포맷·라벨은 `format.ts`만 사용한다. 값·문구를 임의로 바꾸지 않는다.
2. 기준 시각은 `FIXED_NOW`(2026-11-13 15:30:04)다. 화면에서 "현재"는 이 값이다.
3. 등락·손익·매수/매도는 `tone()` 결과(up/down/flat)로 구분하고, 색 외에 부호(+/-)와 텍스트(매수/매도)를 항상 병기한다. 한국식: 상승=up, 하락=down.
4. 금액은 원 단위 정수 + `formatKRW`, 비율은 `formatChangeRate`/`formatPercent`, 수량은 `formatQty`, 지연은 `formatMs`.
5. 숫자 열은 오른쪽 정렬, 텍스트 열은 왼쪽, 상태·구분 배지 열은 가운데 정렬.
6. **AI·승인 원칙 문구(필수 노출)**: AI는 주문을 직접 실행하지 않고 후보만 제안하며, 사람이 승인한 전략(운영중)만 실시간으로 운영된다. 이를 다음처럼 드러낸다.
   - 승인 상태가 «운영중»이 아닌 전략(후보·검증중·승인대기·비활성)에는 항상 «주문 불가» 표기를 붙인다(`orderableLabel`).
   - 전략 관리·AI 전략 연구·사건 분석 화면 상단에 «AI는 주문을 직접 실행하지 않습니다. 승인된 전략만 운영됩니다.» 안내 줄을 둔다.
   - «승인» 버튼은 사람(사용자)만 누를 수 있는 영역에 둔다. 승인 이력에는 승인자·시각을 남긴다.
7. 주문 출처는 «수동» / «전략 자동»(`ORDER_SOURCE_LABEL`) 두 값으로 구분하며, 전략 자동이면 전략명을 함께 표시한다. `source`가 없는 주문은 수동으로 본다.
8. 모든 데이터 영역은 4상태(로딩/빈/에러/정상)를 가진다. 표시 위치는 «영역 본문 자리»(영역 제목은 유지)다. 비교용 구현은 데이터가 항상 있으므로, 상태를 전환해 보여주는 수단(상태 토글 또는 데모 페이지)을 한 곳에 둔다.
   - 로딩: 영역 본문에 자리표시(스켈레톤 또는 스피너).
   - 빈: 영역 본문 가운데에 한 줄 안내 + (있다면) 다음 행동 버튼.
   - 에러: 영역 본문 상단에 오류 메시지 + «다시 시도» 버튼. 영역 나머지는 유지.

## 1. 공통 셸

1. 레이아웃: 좌측 내비, 상단 바, 본문(스크롤 영역)의 3분할. 본문만 스크롤된다.
2. 좌측 내비 상단: 서비스명 «Paper Trading» + 부제 «운영 워크스테이션».
3. 좌측 내비 4그룹(`NAV_GROUPS`): 개요(홈, 계좌·포지션, 포트폴리오) / 트레이딩(주문창, 거래 내역) / 전략(전략 관리, 전략 비교, AI 전략 연구, 사건 분석) / 분석(차트, 백테스트 리포트, 시장 데이터 수집 현황). 그룹 제목은 구분 라벨, 현재 화면 항목은 강조.
4. 좌측 내비 항목 보조 표시: 전략 관리 옆 «승인 대기 N» 개수 배지, 시장 데이터 수집 현황 옆 연결 상태 점(정상/지연/끊김).
5. 좌측 내비는 접기/펼치기 가능. 접으면 항목명을 숨기고 아이콘(또는 첫 글자)만 보인다.
6. 상단 바 왼쪽: 현재 화면 제목(+ 그룹명 경로).
7. 상단 바 ① 계좌 선택: 드롭다운. 항목 = 계좌명 + 거래 모드 배지(`ACCOUNTS` 2개). 선택 시 계좌 기준 화면이 바뀐다.
8. 상단 바 ② 거래 모드 배지: 선택 계좌의 mode를 `LOCAL` / `KIS_PAPER` 텍스트로 표시. 두 모드는 서로 구분되어야 한다.
9. 상단 바 ③ 데이터 갱신 시각: «데이터 15:30:04 기준» + 상태 점(실시간/지연). 클릭하거나 옆 새로고침 버튼으로 수동 갱신(진행 중 표시 포함).
10. 상단 바 ④ 전략 엔진 요약 칩: «엔진 실행 N / 정지 M». 클릭 시 전략 관리로 이동.
11. 상단 바 ⑤ 알림: 종 아이콘 + 미읽음 개수 배지. 누르면 알림 패널(`NOTIFICATIONS`)이 열리고, 항목 = 수준(INFO/WARN/ERROR) + 제목 + 메시지 + 시각. 읽음 처리 버튼, 빈 상태 «새 알림이 없습니다».
12. 상단 바 ⑥ 테마 전환: 라이트/다크 토글(각 시스템이 지원하는 방식으로).
13. 알림 패널 상태: 로딩 = 목록 자리표시, 에러 = 패널 상단 오류 줄.
14. 좁은 화면(폭 768 미만): 좌측 내비는 햄버거 버튼으로 여는 서랍이 된다.

## 2. 홈 — 운영 대시보드 (`getHomeSummary`)

영역: A 시장 지수 줄 / B KPI 카드 줄 / C 전략 엔진 상태 / D 승인 대기 / E 시장 데이터 수집 상태 요약 / F 최근 자동 주문 / G 자산 추이 / H 알림

1. A 시장 지수 줄: `MARKET_INDICES` 4개. 항목 = 이름, 값(÷`INDEX_SCALE`), 전일대비, 등락률.
2. B KPI 카드 6개: 총자산 / 오늘 손익(원+%) / 누적 손익(원+%) / 예수금(+현금 비중%) / 미체결 주문 수 / 오늘 체결 건수. 손익 카드는 tone 표시.
3. C 전략 엔진 상태: 전체 N개 중 실행 중 / 일시정지 / 중지 / 미배포 개수(`engine`). 각 개수 클릭 시 전략 관리로 이동(해당 엔진 상태 필터 적용).
4. D 승인 대기 전략 수 카드: 승인대기 N건, 검증중 M건, «검토하러 가기» 버튼(AI 전략 연구로 이동). 카드에 «승인 전에는 주문이 생성되지 않습니다» 문구.
5. E 수집 상태 요약: 소스별 한 줄(Upbit, 한국투자증권) = 연결 상태 + WebSocket 지연(ms). 클릭 시 시장 데이터 수집 현황으로 이동.
6. F 최근 자동 주문 5건(`recentAutoOrders`): 시각, 전략명, 종목, 매수/매도, 수량, 상태. 모두 «전략 자동» 출처 배지.
7. G 자산 추이: 선택 계좌의 `getEquitySeries` 90일 곡선 + KOSPI 누적수익률 비교. 기간 전환 1주/1개월/3개월(기본 3개월). 범례 포함.
8. H 알림 최근 4건 목록(수준 + 제목 + 시각). 「전체 보기」는 알림 패널을 연다.
9. 상호작용: KPI 카드 클릭 → 관련 화면 이동(총자산→포트폴리오, 미체결→주문창).
10. 상태: B·C·E·F·G 각각 로딩/빈/에러가 영역 본문 자리에 표시된다. F의 빈 문구 «전략이 만든 주문이 없습니다». E 에러 시 «수집 상태를 불러오지 못했습니다».

## 3. 계좌·포지션 (`ACCOUNTS`, `POSITIONS`, `getAccountPnl`, `getSymbolPnl`)

영역: A 계좌 카드 목록 / B 계좌 요약 KPI / C 포지션 표 / D 포지션 상세

1. A 계좌 카드: 계좌당 1장. 계좌명, 거래 모드 배지(`LOCAL` / `KIS_PAPER`), 계좌 유형 배지(PAPER/VIRTUAL), 예수금, 가용 예수금, 활성 여부. 선택된 카드 강조. 선택은 상단 바 계좌 선택과 동기.
2. A 카드 보조: 모드별 설명 한 줄(LOCAL = «로컬 체결 엔진», KIS_PAPER = «한국투자증권 모의투자 연동»).
3. B 요약 KPI 7개: 총자산 / 초기 자본 / 예수금 / 가용 예수금 / 평가금액 / 미실현 손익(원) / 실현 손익(원) + 누적 수익률(%). 손익은 부호+tone.
4. C 포지션 표 열 정의:
   - 종목(왼쪽, 종목명 + 코드 보조 줄)
   - 시장(가운데)
   - 수량(오른쪽, 주)
   - 평균단가(오른쪽, 원)
   - 현재가(오른쪽, 원)
   - 평가금액(오른쪽, 원)
   - 미실현 손익(오른쪽, 원, 부호+tone)
   - 수익률(오른쪽, %, 부호+tone)
   - 비중(오른쪽, %)
   - 당일손익(오른쪽, 원, 부호+tone)
   - 가격소스(가운데, KIS_WS/KIS_REST/LOCAL 배지)
5. C 합계 행(표 맨 아래): 평가금액·미실현 손익·수익률·당일손익 합.
6. C 정렬: 열 머리 클릭으로 오름/내림 전환. 기본 평가금액 내림차순. 정렬 중인 열 표시.
7. C 필터: 종목명/코드 검색 입력, 시장 선택(전체/KOSPI/KOSDAQ/NASDAQ).
8. C 행 선택(단일) → D 영역에 상세. 행 끝에 «주문» 버튼(주문창으로 이동, 종목 사전 선택).
9. D 상세: 매입금액, 평가금액, 미실현 손익, 해당 종목 실현 손익(`getSymbolPnl`), 전략 자동 체결 비중(%), 52주 고저 내 위치(막대).
10. 새로고침 버튼: 포지션 수동 갱신, 진행 중 표시.
11. 상태: A 로딩/빈(«등록된 계좌가 없습니다»)/에러. C 로딩(행 자리표시)/빈(«보유 포지션이 없습니다»)/에러(표 위 오류 줄 + 다시 시도). 현재가가 없는 경우 «-» 표시.

## 4. 포트폴리오 (`getPortfolioAnalysis`, `getEquitySeries`)

영역: A KPI / B 자산 추이 / C 기간 수익률 / D 섹터 비중 / E 종목 기여도 / F 위험 지표

1. A KPI 5개: 총자산 / 투자금액 / 현금 / 총 손익(원+%) / 포지션 수.
2. B 자산 추이: 90일 평가금액 곡선 + KOSPI 대비 누적수익률(두 선), 기간 전환 1개월/3개월(기본 3개월), 범례, 올림 툴팁(날짜·값).
3. C 기간 수익률 표: 행 = 1일/1주/1개월/3개월, 열 = 포트폴리오(%), KOSPI(%), 초과수익(%p, 계산). 오른쪽 정렬, 부호+tone.
4. D 섹터 비중: 도넛 또는 가로 막대(시스템 자유) + 표(섹터, 평가금액, 비중%). «현금» 포함. 비중 내림차순.
5. E 종목 기여도 표: 열 = 종목(왼쪽), 손익(원, 오른쪽), 수익률(%, 오른쪽), 기여 비중(%, 오른쪽). 기본 손익 내림차순, 열 정렬 가능. 이익/손실 구분이 막대 또는 tone으로 보인다.
6. F 위험 지표 카드 6개: 포트폴리오 베타 / 1일 VaR 95%(원 + 총자산 대비 %) / 상위 1종목 집중도(%) / 상위 3종목 집중도(%) / 연환산 변동성(%) / 최대낙폭 MDD(%). 각 카드에 설명(툴팁 또는 보조 문구).
7. 집중도 경고: 상위 1종목 비중 ≥ 25%이면 F 위에 경고 줄(비교 구현은 문구 자리만 두고 비활성 표시 가능).
8. 필터: 계좌 선택(상단 바 연동). 기간 전환은 B에만 적용.
9. 상호작용: D 섹터 항목 클릭 → E 표를 해당 섹터 종목으로 필터(다시 클릭 해제). E 행 클릭 → 해당 종목 차트로 이동.
10. 상태: 각 영역별 로딩/빈/에러. B 에러 시 «벤치마크 데이터 없음» 경고 줄 + 포트폴리오 선만 표시(부분 경고).

## 5. 주문창 (`getStock`, `getOrderBook`, `getRecentTicks`, `estimateOrder`, `ORDERS`)

영역: A 종목 선택 + 종목 헤더 / B 호가 / C 최근 체결 틱 / D 주문 폼 / E 미체결 표 / F 리스크 경고

1. A 종목 선택: 검색 가능한 선택 입력(종목명·코드). 변경 시 B·C·D 갱신.
2. A 종목 헤더: 종목명, 코드, 시장 배지, 섹터, 현재가(큰 글씨), 전일대비(원), 등락률(%, tone), 시가, 고가, 저가, 거래량, 거래대금, 52주 최고·최저(+위치 막대), 베타.
3. A 전략 연관 줄: 이 종목을 대상으로 «운영중» 전략이 있으면 «이 종목을 운영 중인 전략: 전략명(전략 자동 주문 발생 가능)» 한 줄. 없으면 숨김.
4. B 10단계 호가: 매도 10호가(위, 먼 호가→가까운 호가), 현재가 구분선(스프레드), 매수 10호가(아래). 행 = 호가(가격), 잔량(수량), 잔량 막대(최대 잔량 대비 길이). 매도/매수는 tone 외에 위치와 라벨로도 구분.
5. B 하단 요약: 총 매도잔량, 총 매수잔량, 매수/매도 잔량 비율 막대, 스프레드.
6. B 호가 행 클릭 → D 가격 입력에 그 호가가 들어간다(지정가로 전환).
7. C 최근 체결 틱 30건: 시각(왼쪽), 체결가(오른쪽), 수량(오른쪽), 구분(가운데, 매수/매도 tone). 최신이 위.

8. D 구간별 성과 표: 행 = 초반 30일/중반 30일/후반 30일/최근 1주(`segments`), 열 = 선택 대상 각각의 구간 수익률(%) + baseline 열. 셀은 부호+tone, baseline 초과 시 «▲ 초과» 같은 텍스트 표식을 병기.
9. E 복제 계좌 카드(3장): 계좌명, 출처(내 전략/타인 이름), 원본 전략명, 거래 모드 배지, 시작일, 현재 평가금액(원), 누적수익률(%), «복제 설정 보기» 버튼 자리.
10. E 카드 보조: 타인 전략은 «복제본이며 원본과 독립된 별도 계좌에서 운영됩니다» 문구.
11. 전략 성과(내부 전략 12개) 보기: 비교 표 아래 접이식 «전략 버전별 성과» 표(열 = 전략명, 버전, 승인 상태, 기준(실시간 모의/백테스트), 누적수익률, MDD, 샤프, 승률, 손익비). 승인 전 전략은 기준 «백테스트»와 «주문 불가» 배지를 병기.
12. 상태: B·C·D 로딩/빈(«비교할 계좌를 선택하세요»)/에러. 선택이 baseline 하나뿐이면 C는 baseline 선만 표시하고 안내 문구를 보인다.

## 9. AI 전략 연구 (`AI_CANDIDATES`)

영역: A 안내 줄 / B 후보 목록 / C 후보 상세 / D 승인·반려 / E 버전 이력

1. A 안내 줄(고정): «AI는 전략 후보와 근거만 제안합니다. 주문은 사람이 승인한 전략만 실행합니다.»
2. B 후보 목록(좌측 열) 항목: 후보명, 생성일, 상태 배지(후보/검증중/승인대기/운영중/반려), 요약 백테스트 한 줄(누적수익률·MDD), 수정 횟수(예 2/3). 상태 필터 칩, 최신순.
3. C 상세 탭 5개: «근거·설명» / «백테스트·리스크» / «자동 수정 루프» / «전략 DSL» / «버전 이력».
4. C-1 근거·설명: LLM 설명 본문(`rationale`) + 근거 데이터 표(열 = 유형[뉴스/공시/금리/재무/과거 전략 성과/시장 레짐], 제목, 일자, 관련도(%)). 근거가 없으면 제안 자체가 불가하다는 안내(«근거 없는 전략은 제안되지 않습니다»).
5. C-2 백테스트·리스크: 지표 카드 7개(기간, 누적수익률, baseline 수익률, MDD, 샤프, 승률, 손익비) + 회전율(%) + baseline 대비 초과수익. 아래 «리스크 요약» 불릿 목록. 백테스트 전(상태 «후보»)은 «검증 대기 — 백테스트 결과 없음» 빈 표시.
6. C-3 자동 수정 루프: 상단 «수정 N / 최대 M회, 변경 범위 ±K% 이내» 진행 막대. 이력 표 열 = 회차(가운데), 시각(왼쪽), 변경 내용(왼쪽), 변경 이유(왼쪽), 샤프 전→후(오른쪽), 결과(가운데 배지: 개선/변화 없음/되돌림). 한도 도달 시 «수정 횟수 한도 도달 — 루프 종료» 줄.
7. C-4 전략 DSL: 연결된 전략(`linkedStrategyId`)의 DSL JSON 코드 블록. 연결된 전략이 없으면 «DSL 없음(반려됨)».
8. D 승인·반려 영역(상세 하단 고정): 상태가 «승인대기»일 때만 «승인»·«반려» 버튼과 의견 입력(여러 줄) 활성. 그 외는 결정 결과(승인자, 시각, 의견)를 읽기 전용으로 표시. 승인 버튼 옆 고정 문구: «승인하면 이 전략이 실시간 운영 대상이 됩니다».
9. D 승인 확인 단계: 확인창에 전략명·대상 계좌·리스크 제한 요약·백테스트 요약 + «승인 확정»/«취소».
10. D 비활성 사유: 상태가 승인대기가 아니면 버튼 비활성 + 사유(예: «검증 중이라 승인할 수 없습니다»).
11. E 버전 이력: 타임라인 항목 = 버전, 시각, 주체(LLM/LLM(자동 수정)/사용자), 메모. 최신이 위.
12. 상태: B 로딩/빈(«제안된 후보가 없습니다»)/에러, C 로딩/미선택/에러. «검증중» 후보의 C-2는 «검증 진행 중» 상태 표시.

## 10. 사건 분석 (`MARKET_EVENTS`)

영역: A 안내 줄 / B 필터·사건 목록 / C 사건 상세 / D 시나리오 / E 영향 대상 / F 근거 문서 / G 시뮬레이션 상태

1. A 안내 줄: «뉴스·공시·매크로 사건을 분류하고 시나리오별 영향을 시뮬레이션합니다. 결과는 참고 정보이며 주문을 만들지 않습니다.»
2. B 필터: 출처 종류(전체/뉴스/공시/매크로), 사건 유형(전체 + 분류 결과 값: 실적 발표·금리 결정·정책/규제·공급망·M&A·원자재·지정학 등), 시뮬레이션 상태(전체/대기/실행 중/완료/실패), 기간, 검색.
3. B 사건 목록 항목: 일시, 출처 종류 배지, 사건 유형 배지, 제목, 출처 매체, 시뮬레이션 상태 배지. 최신순. 선택 강조. 총 건수.
4. C 상세 헤더: 제목, 일시, 출처, 사건 유형(분류 결과) + 요약문.
5. D 시나리오 3칸(강세/중립/약세): 칸마다 확률(%), 예상 영향률(%, 부호+tone), 예상 영향 기간, 서술. 확률 합 100을 가로 누적 막대로 함께 표시.
6. E 영향 대상: «영향 섹터» 칩 목록 + «영향 종목» 표(열 = 종목(왼쪽), 방향(가운데, 상승/하락/중립), 예상 영향률(오른쪽, %, 부호+tone)). 종목 행 클릭 → 차트로 이동.
7. F 근거 문서 목록: 제목, 출처, 일자. 항목 클릭 시 문서 상세 자리(비교용은 미구현 표시 가능).
8. G 시뮬레이션 상태 영역: 상태 배지(대기/실행 중/완료/실패), 엔진명(«MiroFish + 로컬 LLM»), 시작·종료 시각, 진행률 막대, 시나리오 생성 수. «시뮬레이션 실행/재실행» 버튼(실행 중에는 비활성 + 진행 중 문구).
9. G 상태별 표시: 대기 = D·E는 «시뮬레이션 대기 중 — 결과 없음», 실행 중 = 진행률과 «분석 중», 실패 = 오류 줄 + «재실행», 완료 = D·E 정상.
10. 상호작용: 목록 선택 → C~G 갱신, 시나리오 칸 호버 시 서술 전체 보기, 영향 섹터 칩 클릭 → 목록을 해당 섹터 사건으로 필터.
11. 상태: B 로딩/빈(«수집된 사건이 없습니다»)/에러, C~G 로딩/미선택(«왼쪽에서 사건을 선택하세요»)/에러.

## 11. 차트 (`STOCKS`, `getCandles`)

영역: A 종목 목록 / B 차트 도구줄 / C 캔들+거래량 차트 / D 선택 종목 요약 패널

1. A 종목 목록(좌측 열): 검색 입력, 항목 = 종목명, 코드, 현재가, 등락률(tone). 선택 항목 강조. 정렬: 이름/등락률/거래대금 3택. 시장 필터 칩(전체/KOSPI/KOSDAQ/NASDAQ).
2. B 타임프레임 전환: 1분 / 5분 / 1일(`Timeframe`, 기본 1일).
3. B 지표 토글(여러 개 동시): 이동평균 5/20/60, 볼린저밴드(20, 2σ). 켜진 지표는 범례에 선 이름으로 표시. (지표 값은 구현이 `getCandles` 종가로 계산.)
4. B 보조: 기간 길이 선택(1일봉: 1개월/3개월/전체), 새로고침 버튼.
5. C 가격 패널: 캔들(상승/하락 구분은 tone 방향) + 선택한 이동평균/볼린저 오버레이. Y축 가격(원), X축 시간.
6. C 거래량 패널: 가격 패널 아래 같은 X축 막대. 방향 구분은 캔들과 동일.
7. C 십자선·툴팁: 올리면 시각, 시가/고가/저가/종가, 거래량, 켜진 지표 값을 표시(고정 헤더 줄 또는 툴팁).
8. C 마지막 봉 기준 현재가 표시선. 선택 계좌의 보유 종목이면 평균단가 표시선(라벨 «평단»).
9. D 요약 패널: 종목명, 코드, 시장·섹터 배지, 현재가, 전일대비, 등락률, 시가·고가·저가, 거래량, 거래대금, 52주 고저(+위치 막대), 베타, «주문하기» 버튼, 보유 중이면 «보유: 수량·평균단가·평가손익» 줄.
10. D 지표 요약: 현재 종가의 20일 이동평균 대비 이격(%), 볼린저 밴드 내 위치(%B) 2행. 이 종목을 대상으로 한 운영중 전략이 있으면 «운영 전략: 전략명» 줄.
11. 상태: A 로딩/빈(«검색 결과가 없습니다»)/에러. C 로딩(차트 자리표시)/빈(«표시할 봉이 없습니다»)/에러(차트 위 오류 줄 + 다시 시도). D 로딩/에러.

## 12. 백테스트 리포트 (`BACKTEST`)

영역: A 전략 요약 / B 핵심 KPI / C 누적수익 vs 벤치마크 / D 드로다운 / E 월별 수익률 히트맵 / F 거래 통계 / G 위험지표 / H 팩터 노출 / I 파라미터

1. A 전략 요약 카드: 전략명, 유니버스, 기간(from~to), 초기자본, 최종자본, 벤치마크, 리밸런싱 주기, 비용 모델. 우측에 «리포트 내보내기» 버튼 자리. 카드에 «백테스트 결과이며 승인 전 전략은 주문 불가» 보조 문구.
2. B 핵심 KPI 6개: 총수익률 / CAGR / 벤치마크 수익률 / 초과수익 / 알파(연, %) / 베타. 부호+tone.
3. C 누적수익 곡선: 전략과 벤치마크 두 선(평가금액 또는 누적수익률%), 범례, 올림 툴팁(날짜·두 값·차이). 기간 전환 6개월/1년/전체(기본 전체).
4. D 드로다운 곡선: C와 같은 X축 아래 영역 차트(0 이하), 최대낙폭 지점 표시, MDD 값 라벨.
5. E 월별 수익률 히트맵 표: 행 = 연도, 열 = 1~12월 + 연간 합계. 셀 = 수익률(%, 소수 둘째), 데이터 없는 달은 «-». 셀 배경 강도로 크기를, 부호 tone으로 방향을 표현. 범례(작음~큼).
6. F 거래 통계(`tradeStats`): 거래 수, 승률(%), 손익비, 프로핏 팩터, 평균 수익(%), 평균 손실(%), 평균 보유일, 최대 수익(%), 최대 손실(%), 최대 연속 손실(회).
7. F 승/패 분포: 승률 막대(승 대 패 비율) 한 줄.
8. G 위험지표 표(`riskMetrics`): 항목(왼쪽), 값(오른쪽), 설명(왼쪽 보조). 항목 = 샤프, 소르티노, 칼마, MDD(%), 연 변동성(%), 하방편차(%), 일간 VaR 95%(%).
9. H 팩터 노출 표(`factors`): 팩터(왼쪽), 노출도(오른쪽, 소수 둘째, 부호), t값(오른쪽), 기여(%p, 오른쪽, 부호+tone). 노출도 막대(0 중심) 병기. |t| ≥ 2 항목에 «유의» 표시.
10. I 파라미터 표(`params`): 이름(왼쪽), 값(오른쪽), 범위(오른쪽), 설명(왼쪽).
11. 거래 목록(선택): F 아래 «개별 거래 140건» 접이식 표(번호, 종목, 진입일, 청산일, 보유일, 수익률%). 수익률/보유일 정렬, 승/패 필터.
12. 탭 구성: «성과»(A·B·C·D·E), «위험·통계»(F·G·거래 목록), «팩터·설정»(H·I). 탭 전환 시 상태 유지.
13. 필터: 기간 전환은 C·D에 함께 적용. 그 외 필터 없음.
14. 상태: 각 영역 로딩/에러. 빈 상태는 리포트 전체가 없을 때 «실행된 백테스트가 없습니다» + «백테스트 실행» 버튼(페이지 본문 전체 자리).

## 13. 시장 데이터 수집 현황 (`COLLECTOR_STATUS`)

영역: A 갱신 줄 / B 소스 연결 카드 / C WebSocket 지연 차트 / D Redis 최신가 / E PostgreSQL 히스토리 적재 / F 이벤트 버퍼 / G 오류 로그

1. A 갱신 줄: «기준 시각» + 자동 갱신 주기 문구(«10초 자동 갱신») + 수동 새로고침 버튼(진행 중 표시).
2. A 흐름 요약(한 줄 다이어그램 또는 단계 칩): 외부 API(WebSocket/REST) → 이벤트 버퍼 → Redis(최신가) / PostgreSQL(히스토리 batch). 각 단계에 현재 상태 점.
3. B 소스 연결 카드 2장(Upbit, 한국투자증권): 연결 상태 배지(연결됨/지연/끊김), 연결 시작 시각, 24시간 재연결 횟수, 구독 종목 수, WebSocket 슬롯 사용/최대(막대 + «37/41»).
4. B 채널 행: 카드 안에 채널별(WS, REST) 한 줄 = 채널명, 상태 배지, 지연(ms), 마지막 수신 시각. 지연이 큰 채널은 상태가 «지연».
5. C WebSocket 지연 시계열(최근 60분): Upbit, 한국투자증권 두 선(ms), 범례, 올림 툴팁. 하단 보조 선/막대로 초당 이벤트 수.
6. C 요약 숫자: 소스별 현재 지연, 60분 평균, 60분 최대.
7. D Redis 최신가 영역: 요약(상태, 마지막 갱신 시각, 키 수, 메모리 MB, 적중률 %) + 최신가 표 열 = 키(왼쪽), 종목(왼쪽), 가격(오른쪽, 원), 갱신 시각(왼쪽), 경과(오른쪽, ms, `formatMs`).
8. E PostgreSQL 영역: 요약 KPI(적재 총 행 수, 오늘 적재 행 수, 24시간 batch 건수, 평균 batch 크기, 평균 batch 소요 ms, 실패 batch 수, 마지막 batch 시각) + 테이블 표 열 = 테이블(왼쪽), 행 수(오른쪽), 마지막 batch 시각(왼쪽).
9. F 이벤트 버퍼 영역: 대기 건수 / 용량, 사용률 막대(%), flush 정책 문구(«5초 또는 500건»), 마지막 flush 시각, 24시간 폐기 건수. 폐기가 0보다 크면 경고 표시.
10. G 오류 로그 표(20건) 열: 시각(왼쪽), 출처(가운데: UPBIT/KIS/REDIS/POSTGRES/BUFFER), 수준(가운데 배지: WARN/ERROR), 코드(왼쪽), 메시지(왼쪽), 해결 여부(가운데: 해결/진행 중).
11. G 필터: 출처, 수준, 해결 여부(전체/해결/진행 중). 정렬: 시각(기본 내림), 수준. 행 펼침: 메시지 전체.
12. 상호작용: 소스 카드 클릭 → C·G를 해당 소스로 필터. 지연 차트의 구간 선택은 선택 사항.
13. 상태: B·C·D·E·F·G 각각 로딩/빈/에러. G 빈 문구 «기록된 오류가 없습니다». 소스가 «끊김»이면 B 카드 상단에 오류 줄 + «재연결 시도» 버튼 자리.
