## 1. 제품 정의

- **한 줄:** 모의투자 위에서 내 전략과 AI 의 판단을 검증하는 개인용 투자 실험실. `메모 F`
- **본질:** 투자 상태(주문·체결·잔고·포지션·손익)를 일관되게 유지하는 시스템. 기능이 많아도 이것이 무너지면 전부 무너진다. `메모 I`
- **AI 원칙:** AI 는 주문을 직접 실행하지 않고 후보와 근거만 낸다. 사람이 승인한 전략만 운영된다. `README`

### 사용자 가치 5개 `메모 F`

| 가치 | 사용자가 하는 일 |
|---|---|
| 모의투자 | 가상 계좌로 사고팔고 손익을 본다 |
| 내 전략 테스트 | 규칙을 만들어 과거(백테스트)와 현재(모의 운영)에서 돌린다 |
| «이때 샀으면» | 과거 날짜·금액을 넣어 지금 손익을 본다. 나아가 내 성향 기반 수익률을 본다 |
| AI 끼리 투자 | MiroFish 로 주제를 주고 AI 들이 모의투자한 결과를 본다 |
| 정보 → 투자 계획 | 뉴스·공시·논문·수급 등을 모아 분석을 쌓고 투자 계획과 전략을 세운다 |

## 3. 분석 에이전트군 `메모 B`

공통 요구 2개(메모 B-1·2): 에이전트마다 결과를 DB 에 저장해 «저장된 분석만 따로» 볼 수 있어야 한다. 관심 종목·섹터를 지정하면 그 대상을 분석할 수 있어야 한다.

| 묶음 | 에이전트 | 데이터 출처 | 구현 근거 |
|---|---|---|---|
| 가격·수급 | 차트 분석, 수급(순매수·순매도·공매도·기관·외국인) | KIS·pykrx·yfinance | 🟢 차트 분석·수급 라우트 |
| 기업 | 펀더멘탈, 공시, 실적 발표(earnings call) | SEC, 공시 | 🟠 |
| 정보 | 뉴스, 커뮤니티(Reddit·X), 논문(arXiv·Semantic Scholar), 특허, GitHub, VC 투자·컨퍼런스, 정부 정책 | 메모 B 출처 목록 | 🟠 |
| 거시·사건 | 거시경제, 이벤트, 폴리마켓 | FRED 등 | 🟢 FRED 수집. 🟠 분석 |
| 예측 | TimesFM, Kronos(다음 캔들 흐름 예측), MiroFish(AI 끼리 시뮬레이션) | 모델 | 🟠 |
| 종합 | 종목 추천, 전략 생성, 전략 검증, 실행 판단, 전략 반박·피드백, 여러 AI 전략 비교, 연관관계 추론, 내 포트폴리오 분석 | 위 결과 | 🟠 |

## 4. 단계 제안 `보강`

메모에는 순서가 두 벌 있다(E: 원장→시세 체결→KIS 모의→실전→AI, G: 뼈대→가격→계좌→주문→«이때 샀으면»→전략→백테스트→분석→AI). 현재 코드는 이미 G 의 1~4와 E 의 1~2 를 상당 부분 지났으므로, 남은 것을 이렇게 잇는 안을 제안한다.

| 단계 | 목표 | 들어가는 것 | 왜 이 순서 |
|---|---|---|---|
| 0 | 브로커 계정 연동 | 토스·KIS 계좌·계정 연동(WebSocket·REST: 인증, 계좌·잔고 조회, 시세). 토스 연동은 다른 세션이 진행 중(worktree `docs/toss-open-api-notes` 추정) | 사용자 지시 2026-11-15 «토스연동 먼저», «websocket, rest api 등 계좌 계정 먼저 연동» |
| 1 | 원장 확정 | 부분 체결·취소·홀드/해제 정합성 점검, KIS 모의 reconcile | 본질(상태 일관성). 원장이 흔들리면 이후가 다 무너진다(메모 E5) |
| 2 | 시뮬레이션 | «이때 샀으면», 백테스트 결과 조회 | 엔진이 이미 있고, 메모가 «가장 직관적인 사용자 가치·데모 기능»이라 함 |
| 3 | 전략 | 전략 정의·ON/OFF·로그·전략별 주문, 기본 전략 1개(이동평균 돌파), 위험 성향 프로필(공격적·방어적에 따라 포지션 크기 결정, 잠정) | 전략 보류(TODO)를 여기서 푼다 |
| 4 | 분석 에이전트 1차 | 저장·열람 틀 + 관심 종목·섹터 + 뉴스·공시(신규) + 차트 분석·수급 품질 개선(사용자: «퀄리티가 떨어져서») | 공통 틀을 먼저 세우면 에이전트를 하나씩 붙일 수 있다 |
| 5 | AI 전략 | 전략 생성·검증·반박·승인, 여러 AI 비교, MiroFish | 원장과 전략이 있어야 AI 결과를 저장·평가할 수 있다(메모 E5) |
| 6 | 확장 | TimesFM·Kronos, 폴리마켓, 논문·특허·커뮤니티, 연관관계 추론 | 데이터 출처가 넓고 실험 성격 |
| 마지막 | 실전 주문 | KIS·토스 실계좌 주문 실행 | 실제 돈. paper 정합성 검증 뒤(메모 E4). 0단계 연동과 실주문의 경계는 7장 9번 |

순서는 사용자 확정(2026-11-15), 같은 날 0단계 추가.

## 6. 범위 밖

- 메모 C(작업 방식: CLAUDE.md 인덱스, Plan Mode, 훅·스킬·에이전트, 세션 관리)는 제품 기능이 아니라 개발 습관이다. 이 기획에 넣지 않고 별도로 다룬다 `보강`.
- 거래 일지는 제외로 확정되어 있다(인계 2026-11-15). 단, 메모의 «투자 로그(왜 샀나)»는 거래 내역 안에 둔다.
